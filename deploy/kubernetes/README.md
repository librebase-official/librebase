# Librebase Kubernetes manifests

Static examples and reference for the manifests generated by Studio (`data-studio-ui/lib/k8s-manifests.ts`) and applied via `k8s-provisioner.ts`.

## Required container image

Until a published runtime ships, manifests reference a **stub placeholder**:

```
ghcr.io/librebase-official/lidb-runtime:stub
```

Override with `LIBREBASE_K8S_IMAGE` when running Studio.

The real image must include:

- `lis` supervisor
- lidb embed
- `scripts/lidb_engine.py` at `/opt/librebase/scripts/lidb_engine.py` (for exec probes)
- Writable `/data` mount (`LI_DATA_DIR`)

## Patterns

| Mode | Namespace | Resources |
|------|-----------|-----------|
| **Dedicated** | `librebase-inst-<instanceId>` | Namespace, PVC, ConfigMap, Secret, Deployment, Service |
| **Shared** | `librebase-shared-<orgId>` | One Deployment/PVC/Service per instance + per-project ConfigMaps |

Labels on all resources:

- `librebase.io/org`
- `librebase.io/instance`
- `librebase.io/deployment-mode` (`dedicated` | `shared`)
- `librebase.io/project` (shared project ConfigMaps only)

## Health probes

Liveness uses `lidb_engine.py status` (same JSON contract as local Studio). Readiness uses TCP on the API port.

## Manual apply (dedicated example)

```powershell
kubectl apply -f deploy/kubernetes/dedicated/instance.yaml
```

For production, prefer the Helm chart under `deploy/helm/librebase-instance/` or let Studio provision via `LIBREBASE_RUNTIME=kubernetes`.
