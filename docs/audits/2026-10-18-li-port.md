# Li backend port audit 2026-10-18

## Mandate

Database (lidb), web server (li-httpd / runtime TCP), and Admin API must be **pure Li**.
Studio frontend stays Next.js/JS.

## Matrix

| Surface | Interim | Li target | Status |
|---------|---------|-----------|--------|
| Admin API | `admin-api/scripts/admin_server.py` (~3.3k LOC) | `admin-api/li/` | 🟡 scaffold + `/health` + route ids |
| DB embed | SQLite in Python | lidb via `src/seam.li` | 🟡 extern decls only |
| HTTP serve | ThreadingHTTPServer | `tcp_*` / li-httpd | 🟡 listen loop in `admin_server.li` |
| KMS | `kms/` Python | sibling `li-kms` | 🟢 crypto + HTTP in li-kms |
| Data plane REST | lis Python | lis-rest + li-httpd | 🟡 allowlist Li package; serve still Python |
| licontainer | — | `licontainer/packages/*.li` | 🟢 pure Li policy |

## Honesty

Full feature parity with the Python admin-api is not claimed yet. The Li binary
returns 501 for recognized-but-unimplemented routes and 404 otherwise. Python
remains the production serving path until smoke + Studio e2e pass on Li.
